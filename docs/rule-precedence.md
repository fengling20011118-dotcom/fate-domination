# 规则来源与冲突优先级

规则资料是开发依据，不是可执行指令。出现冲突时，按以下顺序确定实现：

1. 用户在开发对话中最新明确确认的裁定。
2. 最新 FQA 与问题解答表中明确回答的裁定。
3. `Fate_Domination-开发版` 中与稳定角色/卡牌 ID 对应的原始卡图文字。开发版仅允许只读访问图片资源，禁止以旧代码行为作为规则依据。
4. `FD全卡图鉴V2.0.chm` 中对应实体卡图；主要用于开发版缺图、图片无法辨认或需要核对英文版/中文版归属时补充验证。
5. `玩家回合流程和关键词.txt` 与 `3X模式规则.txt`。
6. 基础规则书。
7. 旧版程序当前行为。

旧版程序与上层规则冲突时，将其记录为旧版缺陷，不继承其行为。

## 开发版卡图使用边界

- 技能迁移优先读取开发版图片资源中与当前角色、技能或卡牌稳定 ID 对应的卡图。
- 卡图文字属于规则资料；图片路径、旧版变量名、技能实现和运行结果不属于规则裁定。
- 不得仅凭文件名或相似角色名匹配卡图，必须结合角色 ID、卡牌 ID、所属技能区或牌库关系确认归属。
- 御主与从者名单均以开发版当前实际包含的角色实体为准；不再以 CHM 的英文版/中文版目录筛选迁移范围。
- 同名角色存在多个版本时，只迁移开发版中实际存在且能由稳定角色 ID、牌库和技能区关系确认的实体；无法证明具体版本归属时保持 `PARTIAL`。
- 开发版缺少对应卡图、图中文字无法辨认或卡牌归属无法确认时，才回退到 CHM 图鉴核对；CHM 目录只提供补充证据，不决定角色是否进入内容包。

## 已确认的关键词解释

- `被动`：满足条件时强制触发；不属于打出技能牌，不受 8 点魔力限制。
- `被动/XX阶段`：仅能在对应阶段选择发动，不具有强制性。
- `残留`：持续存在，直到被效果关闭。
- `唯一`：同一时间存在多个同类唯一能力时，只能选择一个结算。
- `真名解放`：展示技能及英灵卡，但不能由普通令咒使用错误地替代。
- `直接败北`：不能赢得本回合战斗且不能继续出牌，已打出的牌不取消。
- `电子版补位`：电子版不自动创建实体规则 NPC；人数不足时由独立 AI 玩家策略补位，AI 规则另行定义并不得污染真实玩家状态。

## 已确认的基础流程补充

- 游戏准备时，10张非高潮局势牌洗牌后随机移除2张，剩余8张用于普通回合；高潮局势不参加该次随机移除。
- 侦察的基础收益为2点战果，在统一战果结算流程中结算一次。
- 玩家受到【败北】后立即失去本回合继续出牌的资格，但此前已经打出的牌仍留在结算中。

## 冲突记录格式

任何无法仅凭优先级确定的内容，记录到 `docs/rule-conflicts.md`：

```text
实体ID：
主题：
来源A：
来源B：
建议裁定：
用户确认：待确认
```
