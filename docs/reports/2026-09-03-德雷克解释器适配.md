## 3. 新增后端接口与真实接入缺口

### 同批出牌

`playAbilityCardBatch(state, playerId, choices)` 是可信后端调用，先按批次支付前状态校验、合计费用、同时激活，然后发出带同批快照的打出事件。它不是客户端命令。客户端不能提交批次条件、效果或历史计数。

外围行动协调器仍需验证常规两张名额、必须纳入的手牌、常规移动先于出牌以及战场至少一张明置等整回合规则，再调用该接口。本次没有将其假装为完整常规出牌入口；旧 GameLoop 的常规出牌尚未改为调用此接口。

坐骑召唤的选牌通过现有 `activate_ability → choose_target` 接口执行。目标、费用与结算由后端决定，其他玩家只得到“等待响应结算”。这条效果出牌不占常规出牌名额。

### 事件战果

新增可选 `victoryPoints`，贯通 `ScheduledEventDrawState → RoundStartEventDraw → EventPlacementState`。这是内容层供应的权威事件印刷 VP，不接受玩家提交，也不把缺失值当作 0。

领取后的实体事件保留在 `GameState.eventDiscardPile`，并从 `eventPlacements` 移除，避免技能重复领取。现有旧事件内容桥尚未完成每张牌 VP 的可靠映射，弃牌回洗和正式内容库也尚未接通；不能据此宣称完整事件牌库生命周期已实现。没有把含义不同的 `competitionReward` 擅自当作事件 VP。

### 基础牌、主线与 UI

12 张牌库引用保留核对到的 canonical ID，解释器加载器不会从 ID 猜基础牌定义。行为测试为基础牌提供显式 fixture；正式游戏必须由内容层加载这些真实定义。

本次只改本地解释器切片及必要的事件字段传递，没有修改主仓库集成契约、安装路由或桌面前端。NPC 必须进入权威交战状态才能参与“无人与你对战”的判断；现有基础玩家检查不构成所有 NPC 机制的完成证明。

## 4. 暴风雨的航海家：保留完整语义，暂不开放

已记录费用 2、威力公式 X、真名解放、急行逆向移动 modifier 和战斗阶段劫掠，但整张牌禁用，未标记为可自动执行。

2026-09-03 后续用户已确认：

1. 移动距离按基础路线箭头段数，不是消耗魔力。工房→深山町、深山町→新都、新都→侦察各为 1；工房→新都为 2、→侦察为 3。任意地点移动在此基础路线也按起终点距离计数，不能因免费而算 0。独立扩展地点的连线未给定时不猜测。
2. 劫掠反复经过同一战场重复计数，经过与停留不合并；保留独立记录，不按地点 ID 去重。
3. 黄金鹿的“无人与你对战”事件奖励仅在战场触发，包括深山町、新都及启用时的月杯等。工房不触发；侦察仍按独立条款获得 2 VP。

以上已写入 authoring 的 `userConfirmedInterpretations` 和 `resolvedQuestions`，并随机器报告输出。航海家两项能力已从“文本未确认”改为“规则口径已确认、处理器未实现”的 unsupported，仍未开放自动执行。

原先问项中的“初始部署后从未移动是否算一次停留”尚未直接回答，拆分留在 openQuestions，待接入停留记录产生时点时确认。不能据“不合并”自行认定一次落点必定同时产生一条经过和一条停留。

战场边界回归发现月杯默认地图缺少 battlefield 标记，已补正；默认启用状态未改变，未引入月之癌角色或月杯事件组。工房/侦察的事件奖励排除与启用月杯的奖励分支均有定向测试。

已知待实现：急行逆向移动必须接入真实移动合法性入口及历史日志。它是“被动”，不能错误地要求航海家已打出才生效；不能只在公式里增加一个布尔值就算完成。

未回答问项保存在 authoring 的 openQuestions，并出现在机器报告。尚未接入的历史公式在加载时报告 unsupported，不能由客户端填入 X。适配报告会聚合卡牌状态：某条 reveal 能力可执行，不代表整张未完成卡牌可打出。
