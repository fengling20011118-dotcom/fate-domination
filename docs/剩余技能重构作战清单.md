## 二、重构的标准姿势（正确做法）

**入口**：`src/content/confirmed-skill-overrides.ts`（或 `structured-*-batch.ts` 子文件）

**一个技能要被判定 FULL，必须同时满足：**
```ts
{
  handlerId: "core.structured-skill",   // 通用 DSL，或已实现的专属 handler
  supportLevel: "FULL",
  rules: {
    schemaVersion: "fd-card-authoring-v1",
    abilities: [ /* 每条 execution.mode: "automatic"，用 effect DSL 精确表达 */ ],
  },
}
```

**判定链路**（`skill-package.ts` line 96）：
```
supportLevel = confirmed?.supportLevel ?? parsedSupport(handlerId已注册?FULL) ?? toSupportLevel(implementation)
```

**验收标准**（`skill-development-workflow.md` + `rule-audit.md`）：
- FULL 必须有**实际执行语义**，无未解析条款是最终验收条件
- **骨架 / handler 标签不能代替验收**——写错了比不写更糟（错误自动结算污染引擎）

**验证命令**：
```bash
npm run audit:skills          # 看 FULL/PARTIAL 数量
npm run validate              # 内容校验
npm test                      # 完整回归测试
npm run gaps:skills -- --skill <技能ID>   # 查单个技能的未解析条款
```

## 三、通用 DSL（core.structured-skill）能力清单

### 支持的 effect（`executeStructuredEffects`，约 70 种，`skill-handlers.ts` line 2214 起）
- 资源：`gain_mana` / `lose_victory_points` / `gain_victory_points` / `gain_victory_points_per_target` / `pay_mana`
- 抽牌：`draw_cards` / `discard_all_hand` / `discard_selected_cards` / `discard_selected_hand_and_draw`
- 移动/转移：`move_forward` / `move_player` / `move_selected_cards` / `transfer_selected_cards` / `return_cards_by_definitions`
- 威力：`combat_power_bonus` / `source_card_power_bonus` / `add_card_cost_modifier`
- 选择：`choose_cards` / `choose_one` / `look_target_deck_top_discard_selected_keep_rest` / `look_deck_top_choose_one_to_hand_discard_rest`
- 状态：`defeat_player` / `close_selected_card` / `close_owned_active_cards_by_definition` / `set_player_flag` / `increment_player_flag` / `add_player_flag_number`
- 真名：`reveal_true_name` / `hide_true_name`
- 其他：`create_card_instances` / `activate_owned_skill_card` / `deactivate_owned_skill_card` / `remove_selected_cards` / `schedule_effect` / `if_condition` / `info_note`

### 支持的 condition（`assertStructuredConditions`，26 种）
`source_active` / `at_battlefield` / `location_is` / `location_in` / `phase_is` / `event_type_is` / `event_player_is_controller` / `event_definition_is_self` / `event_face_is` / `event_player_won_combat` / `event_player_lost_combat` / `event_eliminated_same_battlefield_player` / `player_flag_equals` / `player_flag_number_at_least` / `player_flag_number_current_round` / `player_flag_number_not_current_round` / `true_name_hidden` / `true_name_revealed` / `target_count_at_least` / `target_count_equals` / `target_command_seals_at_most` / `target_command_seals_equals` / `owned_active_card_by_definition`

### **DSL 的能力缺口（导致大量技能无法覆盖）**
- ❌ **无数值条件**：没有 `mana_at_most`、`victory_points_at_least` 等数值比较条件（"魔力≤2"无法表达）
- ❌ **无否定条件**：没有"未战败"、"非X属性"等否定/排除条件（"除非战败"无法表达）
- ❌ **无 set 效果**：没有"将魔力设为N"的 set（"魔力设为4点"无法表达）
- ❌ **无动态公式的完整支持**：`X=威力/5向下取整` 这类复杂公式部分支持
- ❌ **无专属状态系统**：宝石/杀戮冲动/兽/异闻带/月之圣杯等专属状态需专属 handler
