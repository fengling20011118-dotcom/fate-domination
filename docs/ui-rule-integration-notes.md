# 战斗 UI 与规则层接入约定

本文记录当前本地 UI 样稿中仍由前端模拟的部分，供后续接入规则引擎、联机房间和服务端计时时使用。UI 演示不得成为最终规则判定来源。

## 公共弃牌堆

- 侦察区域只显示一个公共弃牌堆，数量为局势弃牌与事件弃牌之和。
- 点击后，弹窗仍按“局势牌”和“事件牌”分栏显示正面卡牌。
- 数据层应继续保留 `situationDiscard` 与 `eventDiscard` 两个集合，不能因为外观合并而混成一个无类型数组。
- 结算完成后才把本回合生效的局势牌和事件牌加入弃牌堆。
- 原始局势牌堆和事件牌堆的背面不提供点击查看功能。

## 行动计时

每名玩家维护以下权威状态：

- `turnAllowanceMs = 90_000`：每轮免费行动时间。
- `timeBankMs = 1_200_000`：整局总时长，跨轮保留。
- 玩家完成入场、发牌等不可操作演出后，才开始本轮计时。
- 免费时间耗尽后才扣除总时长。
- 总时长在本轮中耗尽时立即触发超时行动；后续各轮在 90 秒耗尽后触发超时行动。
- 联机模式必须由房主或服务端更新时间并广播快照。浏览器的 `setInterval` 仅用于显示，不能作为权威计时。
- 自动出牌必须调用规则层提供的合法行动生成器。当前 UI 样稿只用“选择基础威力最高的两张未出牌”演示交互，不代表最终规则。

建议命令接口：

```ts
previewAction(command): ProjectedActionResult
commitAction(command, expectedRevision): ActionResult
resolveTimeout(playerId, expectedRevision): ActionResult
```

## 技能与技能卡

- 全局统一的技能确认弹窗已移除，不能只凭“技能”名称决定是否二次确认。
- 正式技能交互必须由规则层元数据或 resolveSkillInteraction 接口返回 attack-card、on-use 或 ability；前端不得通过威力、卡图、名称或效果文本正则自行猜测。当前少量显式映射只用于本地 UI 样稿。
- 对魔力、风王结界、誓约胜利之剑等效果写明在战斗阶段参与攻击结算的技能视为可出牌技能卡：点击“使用技能”后先加入本次出牌选择，再点击该卡或点击“取消使用”即可撤回。
- 技能卡与普通攻击卡共享本次出牌数量限制，点击“确认出牌”后才提交并结算。
- 无限剑制的效果明确写有“打出时”，属于使用后立即执行该段效果的技能；点击“使用技能”后立即进入手牌重组流程，不占两张攻击牌的选择位置。
- 带选项的能力仍先选择效果并确认选项，例如宝石的具体效果。
- 不作为卡牌打出的普通主动能力可直接发送使用意图，但魔力、次数、令咒和状态仍须由规则层验证并原子修改。
- UI 中御主与从者技能的操作按钮统一显示“使用技能”；技能卡暂存后显示“取消使用”。

## 确认出牌前的威力计算

- 对魔力、誓约胜利之剑等依赖“确认出牌”后才使用或触发的牌，选择阶段只做预览，不能直接结算技能。
- 威力结果应由规则层的只读模拟接口返回，至少包括基础攻击、局势、事件、地利、状态、技能与其他持续效果。
- 预览必须无副作用，不扣资源、不移动卡牌、不公开隐藏信息。
- 前端显示“威力”，并在规则层拒绝提交或状态版本变化后重新计算。
- 当前 UI 的局势、地利和事件加成是演示用近似计算；接入规则层后必须删除该近似逻辑，改用权威模拟结果。

## 联机一致性

所有确认操作都应携带对局版本号。服务端若发现版本已变化，应拒绝旧预览对应的提交并返回新状态，由客户端重新显示预计结果。
