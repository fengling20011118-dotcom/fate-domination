# Fate/Domination 桌面端 UI 参考稿

这是一个不依赖构建工具的交互原型，用于向仓库作者说明桌面端完整对局界面的信息架构与操作方式。它不是规则引擎，也不代表最终美术资源。

## 本地预览

在本目录启动任意静态文件服务器，例如：

```powershell
python -m http.server 4178 --bind 127.0.0.1
```

然后打开 `http://127.0.0.1:4178/`。当前参考断点以 1440×900 和 1920×1080 为主；低于 1180px 会显示桌面端提示页。

## 已实现的参考交互

- 展开或收起玩家操作台；展开时仍保留阶段决策栏。
- 鼠标悬停任意可见卡牌时显示固定位置的中文速览；单击后打开屏幕居中的完整卡牌检视。
- 事件牌、局势牌、地点效果牌和其他玩家已公开技能牌与玩家手牌使用同一套检视组件。
- 自己回合单击自己区域内的技能牌或手牌后，在完整检视层选择加入或移出本次出牌。
- 常规牌不足两张时，追加牌自动退出选择，确认按钮不可用。
- 非本人回合以及查看公共/其他玩家卡牌时仅显示卡牌信息，不显示操作按钮。
- 点击其他玩家席位，打开只含公开信息的玩家抽屉；按 `Esc` 或关闭按钮返回。

## 设计边界

- 牌面图片仅为参考素材；卡牌说明与数值应由结构化卡牌数据提供，不能依赖用户从缩略图中辨认小字。
- 出牌点击表示玩家提出操作，最终合法性仍由后端规则引擎裁定。
- 完整检视层的按钮应由后端 `availableActions` 提供；客户端不得根据卡牌名称自行猜测合法动作。
- “追加”是独立于常规两张的显示层，不应被计入 `2 / 2`。
- 御主与从者的私密信息只在所有者视图出现；其他玩家抽屉仅显示公开快照。
- 中文规则复述是经过人工确认的结构化静态字段，不在玩家悬停时调用大语言模型生成。
- 移动端完整对局将省略悬停速览，点击卡牌后进入全屏检视；本原型暂未实现移动布局。

## 权限矩阵

| 状态 | 自己区域内的卡牌 | 公共或其他玩家卡牌 |
|---|---|---|
| 自己的行动回合 | 查看；显示后端返回的合法操作 | 仅查看 |
| 自己的其他阶段 | 查看；仅显示当前阶段合法操作 | 仅查看 |
| 非本人回合 | 仅查看；响应窗口开放时例外 | 仅查看 |
| 房主代理 | 使用被代理玩家的权限 | 仅查看 |

产品目标与视觉规则分别见 [PRODUCT.md](./PRODUCT.md) 和 [DESIGN.md](./DESIGN.md)。
